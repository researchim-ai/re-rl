# Проверка качества вычисляемых трейсов

`algorithm_trace` должен формироваться во время вычисления ответа. Простое наличие `solution_steps`, совпадение финального ответа с `verify()` или несколько строк текста не доказывают полноту решения.

## Что проверяет аудит

```bash
python scripts/audit_task_traces.py
MPLCONFIGDIR=/tmp/re-rl-mpl python scripts/audit_task_traces.py --runtime
```

Аудит проходит оба реестра. Статические индикаторы выделяют методы `solve()`, которые используют заранее вычисленные итоги без прохода по данным. Это кандидаты для ручной проверки: одношаговая формула может быть полноценным решением, а наличие цикла в коде ещё не гарантирует качество объяснения.

Режим `--runtime` проверяет генерацию на RU/EN, сложности 5, seed 31. Каждый запуск ограничен по времени и изолирован в отдельном процессе (режим требует поддержки `fork`). Сигнатуры старых фабрик учитываются явно; ошибки внутри генераторов не скрываются. Успешная генерация означает работоспособность этого экземпляра, а не математическую сертификацию типа.

`trace_audit.json` хранит машинный список всех типов, исходных файлов и результатов. `needs_review` — очередь проверки, не вердикт об ошибке. `reviewed_with_regression_tests` отмечает только семейства с добавленными проверками вычислений.

## Новый контракт для точных вычислений

`re_rl/tasks/computation_trace.py` предоставляет `ExactTrace.calc(label, operation, *operands)`: операция действительно выполняется на `Fraction`, и одновременно сохраняются аргументы и результат. Следующий шаг алгоритма использует возвращённое значение. Это не печать уже известного ответа.

- `algorithm_trace`: операции, аргументы, метки состояния и результаты;
- `computation_inputs`: исходные данные без потери точности дробей;
- `solution_steps`: локализованное представление вычислений и финальный ответ.

Данные сохраняются через `get_result()` и `DatasetGenerator.generate_single_task()`. Существующие SFT/Chat/VLM конвейеры используют подробные текстовые шаги. Для хранения отдельных структурированных событий сохраняйте результаты задач или `generate_single_task()`.

Специализированные вычислители, созданные до общего аудита, покрывают 14 ML-, 11 RL-, 20 математических DP/счётных и 2 физических семейства; их списки находятся в соответствующих `detailed_solvers.py` и `math/algorithm_traces/solvers.py`. Физические схемы записывают чтение листьев, редукцию каждого узла и повторный расчёт после переключения. Для суммы листьев сопротивления не редуцируются. Также покрыты логические схемы и ДКА, включая оба визуальных варианта: каждый вентиль на каждом наборе входов, каждый переход автомата и проверка принимающего состояния. Графовое покрытие перечислено отдельно в `graph_algorithms_shared/coverage.py`.

Трейсы одношаговых RL-задач описывают именно заданное обновление. Они не являются журналом полноценного обучения агента в окружении.

## Текущий результат аудита

Очередь из 124 кандидатов полностью обработана. Все они повторно вычисляют решение из входных данных и экспортируют `algorithm_trace` и `computation_inputs`. В сумме отдельными регрессиями исполнения покрыто 259 типов. Проверка генерации всех 1022 типов на RU/EN даёт 2044 успешных запуска на сложности 5.

Для 124 ранее существовавших семейств вычисления и форматирование разделены: `solve()` запускает проверенный вычислитель, а `_solve_before_trace()` сохраняет совместимый формат ответа. Последний не является вычислителем и не используется как источник ответа. Для AC и конвертации единиц исходный метод уже выполнял настоящие вычисления; он запускается под наблюдением исполнения.

Используются три формы событий:

- математические операции с точными дробями, аргументами и результатом;
- фактически исполненные операторы Python, вызовы, изменения локального состояния и возвраты; `next_line` фиксирует продолжение выбранной ветви;
- игровые состояния, оценки законных ходов, минимаксная свёртка и обращения к мемоизированным результатам.

Операторы Python — технический трейс исполнения, а не автоматически написанное математическое доказательство. Он сохраняет действительные вычисления. Комментарии исходного кода не попадают в текст. Снимки состояния копируются в момент события. Перехват исполнения действует только в текущем потоке и восстанавливается даже при исключении. Случайное построение экземпляра не входит в трейс решения.

Формульные и обратные задачи используют явно заданные величины условия. Восстановление секретов использует доли, логическая таблица решается из подсказок, неизвестная масса подвеса восстанавливается из моментов без чтения скрытой массы или закэшированных масс стержней. Дробные степени вычисляются точно для рациональных корней; для иррациональных результатов сохраняется численное приближение.

Статический аудит продолжает показывать признаки старых форматтеров даже после исправления вычислителя (`delegated_execution`), чтобы переименование метода не скрывало кандидатов. `remaining_static_review = 0` означает закрытие этой конкретной очереди, а не формальное доказательство корректности всех 1022 семейств. Дополнительный просмотр методов с циклами обнаружил полноценные ранее собранные пошаговые журналы (например, gate_fold и ucb_bandit); цикл сам по себе не служит ни гарантией качества, ни признаком заглушки.

```bash
python -m pytest tests web/test_web.py -q
```

Новые регрессии перебирают все 146 типов, подтипы, сложности 1–10 и RU/EN. Проверяются исходные независимые ответы конструктора, оценка проверяющим, JSON-экспорт, повторяемость полного трейса и устойчивость к подмене `answer`/`_answer`. Отдельные проверки подтверждают реальные изменения стека, ветвления, неизменность снимков, восстановление перехвата и точные корни.

Дополнительно к исходным 124 типам исправлены `binary_search`, `kmp_matching`, `game_of_life`, `game_of_life_image` и `elementary_ca`. У двоичного поиска записаны границы и сравнения; у KMP — префиксные переходы, откаты и перекрывающиеся совпадения. У клеточных автоматов каждая клетка получает новый бит из предыдущего поколения, с явными соседями и нулевыми внешними границами. ## Индукция и скрытые ответы

После исходной очереди дополнительно проверены truth_table, three_sat, arc_grid_induction и arc_grid_image. Таблица истинности заново оценивает каждый набор и каждую подформулу. 3-SAT использует DPLL (единичные клаузы, ветвление, конфликт, откат), а не сохранённый `hidden`. Проверяющий по-прежнему принимает любое удовлетворяющее присваивание. Невыполнимая формула получает явный ответ, подтверждённый исчерпанием ветвей.

ARC рассматривает явно перечисленное в условии семейство преобразований. Для каждого кандидата записаны проверки примеров и предсказание тестовой сетки. Готовый `test_out`, функция `fn` и скрытое имя правила не используются как вход. Если подходящие правила дают разные тестовые результаты, примеры неоднозначны: решатель отклоняет их, генератор строит новый экземпляр. Не требуется уникальность имени правила, если все предсказания совпадают. При отрисовке учитываются высота выходной сетки и ширина заголовка.

`tests/test_inference_traces.py` сверяет DPLL с полным перебором всех 256 подмножеств небольшого набора клауз, проверяет конфликтную ветвь, граничные классификации, неоднозначность ARC, подмену генераторских секретов и компоновку изображения. Для четырёх новых типов также действует общий прогон уровней 1–10 и RU/EN.

Дополнительно исправлен `kmeans_step`: вычисляются квадратные расстояния по координатам, сравнение с выбором первого кластера при равенстве, накопление числа точек и суммы x, точное деление для нового центроида. Подтип nearest использует только запрос и центры, не скрытую обучающую выборку. Для пустого первого кластера среднее не выдумывается: возвращается ошибка empty_cluster. Добавлены проверки равных расстояний, точной координаты и пустого кластера.

Статический фильтр расширен на hidden/test_out/klass/grid/row/pi/count. Чтения проверяются именно у self, чтобы математическая константа math.pi не помечалась как готовый ответ. Отдельная регрессия закрепляет обнаружение скрытого ответа, сетки и классификации.

## Поиск по ограничениям в сеточных головоломках

Для binary_puzzle, nonogram и battleship сохранённая сетка sol больше не является входом решателя. В такузу и нонограммах строятся допустимые варианты каждой строки и каждого столбца. Пересечения удаляют неподдерживаемые варианты с координатой и множеством допустимых значений в качестве свидетеля; в такузу дополнительно исключаются повторяющиеся завершённые линии. Поиск выбирает минимальный неоднозначный домен, перебирает варианты и явно записывает откаты. Проверяющий принимает любую корректную сетку, не только исходную генераторскую.

Battleship перечисляет прямые размещения кораблей с битовыми масками. Поиск проверяет пересечения, касания, остатки квот строк/столбцов и достаточность свободных клеток. Одинаковые корабли перебираются в порядке индексов размещений, исключающем перестановки одного набора. Ошибочные fallback генераторов (некорректная сетка такузу или пустое поле при ненулевом флоте) заменены явной ошибкой generation_failed. Уникальность строк и столбцов проверяется уже во время построения такузу.

В tests/test_grid_search_traces.py используются: все 64 бинарные сетки 2×3 для нонограмм; все 81 частичное условие такузу 2×2; все 512 сеток 3×3 для независимого построения возможных флотских условий; подмена sol; воспроизведение свидетелей исключений; откаты; неизменность записанного результата после мутации сетки; отказ генератора вместо некорректного fallback.

На 20 экземплярах сложности 10 каждого типа медианное время только solve() на текущей машине составило около 1,64 мс (такузу), 0,90 мс (нонограмма) и 2,11 мс (Battleship), включая формирование текста и событий. Максимумы в этом замере — 2,48 / 2,50 / 5,63 мс. Это локальный замер для размеров из пресетов, не обещание для произвольных размеров; поиск в общем случае экспоненциален.

Аудит теперь отдельно распознаёт rendered_cached_grid: форматирующий генератор выражений над self.sol/self.solution не считается вычислительным алгоритмом. Это расширяет старую очередь: новые кандидаты (kakuro, kenken, magic_square, magic_square_image, n_queens, skyscrapers) были выделены и затем исправлены в следующем проходе; нулевое число кандидатов прежнего фильтра не было доказательством отсутствия других заглушек.

## Закрытие очереди арифметических CSP

Исправлены все шесть кандидатов форматирования сохранённой сетки. Kakuro восстанавливает B,C,D,E из выбранного A и четырёх сумм, проверяет диапазон 1..9 и различие цифр внутри линий; его проверяющий теперь также явно отклоняет значения вне диапазона. Генератор проверяет единственность быстрым точным перебором и больше не возвращает заведомо неоднозначный fallback.

KenKen и magic_square используют конечные домены, таблицы арифметических ограничений, исключение уже занятых значений в группах all-different, выбор минимального неоднозначного домена и откаты. Для каждого исключения сохраняются поддерживающие значения или уже занявшая значение переменная. У магического квадрата входом служат отдельные given, а проверяющий проверяет подсказки, числа 1..9 и все восемь сумм, независимо от сохранённого solution. Визуальная версия также читает given при отрисовке.

Skyscrapers вычисляет видимость каждого здания в обоих направлениях для каждой перестановки строки/столбца, затем согласует линии по пересечениям. NQueens использует битовые маски столбцов и диагоналей, записывает доступные столбцы, постановки, тупики, возвраты, найденные размещения и накопленный счётчик. Подтип solve завершает поиск на первом результате; count перебирает все ветви. Параметр task_type у ферзей теперь действительно выбирает подтип.

Форматы solution сохранены: кортеж у Kakuro/MagicSquare, кортежи строк у KenKen/Skyscrapers, список столбцов у NQueens. Проверяются все подтипы, RU/EN, сложности 1–10, подмена сохранённых решений, независимые переборы и воспроизведение доступных ходов и откатов ферзей. Текущее remaining_static_review = 0 относится к расширенному фильтру и закрытой очереди, а не является формальным сертификатом всех 1022 типов.

В текстовых шагах KenKen и Skyscrapers каждый проверенный арифметический набор / порядок высот показывается отдельно; структурированные события сохраняют все вычисленные результаты и проходы видимости. Локальный замер на пяти экземплярах сложности 10 дал медиану solve() около 0,07 мс для Kakuro, 1,18 мс для KenKen, 0,81 мс для MagicSquare, 2,35 мс для Skyscrapers и 19,27 мс для полного подсчёта NQueens при n=8. Время включает сборку событий и текста, но не построение случайного экземпляра; это не гарантия для других размеров.

Пересборка статического каталога и сайта теперь пишет PNG, HTML и data.js через временный файл в том же каталоге и атомарную замену. PNG проверяется перед заменой. При ошибке остаётся предыдущий полный файл, временные файлы удаляются. Это атомарность отдельных файлов, не транзакция всего каталога. tests/test_atomic_static_assets.py проверяет чтение старой картинки во время незавершённой записи, сохранение старого файла при ошибке/невалидном PNG, очистку временных файлов и права доступа.

## Поиск вместо генераторских ответов: Hitori, Star Battle, Sudoku

Hitori решается только из числовой сетки. Совпадающие числа в линии требуют затенить хотя бы одну клетку; затенение исключает соседние затенения. Поиск записывает принудительные значения, ветви и откаты. Связность проверяется обходом потенциально белых клеток (для отсечения несовместимых частичных состояний) и отдельно на полном заполнении. Сохраняются каждый шаг очереди, открытые клетки и множество достигнутых клеток. Попытка оставить остальные клетки белыми обозначена как пробное заполнение, а не как логически вынужденный вывод.

Star Battle решается только из карты областей с проверкой использованных строк, столбцов, областей и касаний. Случайный генератор больше не возвращает заведомо неверную диагональную расстановку при неудаче: резервный путь также выполняет точный поиск. У обоих координатных проверяющих исправлена возможность отбросить нечётный хвост ответа; повторяющиеся пары и дробные координаты отклоняются. Явный ответ none/нет или пустой список допустим для Hitori, если по правилам закрашивать ничего не нужно; произвольный текст не становится пустым ответом.

Sudoku полностью решается из puzzle через маски строк, столбцов и блоков, MRV и возврат. Записываются сканирования кандидатов, присваивания, противоречия, возвраты и полные решения. Метод _has_unique_solution действительно ищет до двух решений. Обычный проверяющий принимает любую сетку, соблюдающую исходные подсказки и правила, включая блоки; сохранённый solution не является эталоном проверки. Явный hints_ratio=0 теперь сохраняется, неверные размеры и доли подсказок отклоняются.

В визуальном судоку значение выделенной клетки доказывается повторным поиском с запретом найденного значения. Если найдено другое значение, solve сообщает ambiguous_target. При построении экземпляра генератор добавляет публичные подсказки только при наличии настоящего контрпримера, пока значение клетки не станет однозначным; сама выделенная клетка остаётся пустой. Это может увеличить число подсказок относительно желаемой доли. Число в target_value не является входом решения или проверки. Вычисленный сертификат привязан к неизменяемому снимку puzzle и target; изменение условия аннулирует сертификат.

tests/test_board_search_traces.py проверяет все входы Hitori 2×2 полным перебором затенений, Star Battle перебором перестановок, Sudoku 4×4 по всем 288 корректным полным сеткам, альтернативные ответы, неоднозначную выделенную клетку, пустую/полную исходную сетку, подмену сохранённых ответов, шаги очереди BFS и кандидаты судоку по фактическим присваиваниям.

## Навигация, пятнашки и переправы

Ещё пять типов включены в независимое повторное вычисление: sliding_puzzle, sliding_puzzle_image, grid_navigation, grid_navigation_image, river_crossing. Поле пятнашек решается из board и n: записываются сравнения пар для инверсий и проверка чётности с номером строки пустой клетки снизу. A* сохраняет извлечения с g/h/f, устаревшие элементы, каждый допустимый ход пустой клетки, старую оценку, решение об обновлении и восстановленный кратчайший маршрут. Эвристика — сумма манхэттенских расстояний плиток. В событиях хранятся только затронутые состояния и размеры очереди, а не копии всей кучи и таблицы расстояний на каждом шаге.

Навигация по командам пересчитывает каждое перемещение/поворот из start_dir и commands, сохраняя состояние до/после; направления закодированы N/E/S/W = 0/1/2/3. Исправлена передача task_type для выбора подтипа и использование языка при построении текста команд до инициализации BaseTask. BFS лабиринта сохраняет извлечения, проверки всех четырёх соседей (границы, стены, посещённость), расстояния и восстановленный маршрут; отдельно обрабатываются заблокированные концы и исчерпание очереди. Координаты (x,y), индексы от 0. Сохранённые end_x/end_y/end_dir и готовые ответы не являются входом вычисления.

У переправы ревнивых пар ранее вызывался алгоритм миссионеров и каннибалов — это изменяло саму задачу. Теперь BFS использует идентичности всех супругов (2*i — муж, 2*i+1 — жена), маску правого берега и сторону лодки. Проверяется вместимость, наличие пассажиров на нужном берегу, безопасность обоих берегов и самой лодки. Форматтер перечисляет настоящих участников. Другие два подтипа повторно выполняют свои BFS под наблюдением ExecutionTrace. Путь восстанавливается по родителям, длина минимальна при единичной стоимости переправы.

В tests/test_navigation_search_traces.py проверены все перестановки пятнашек 2×2, все состояния 3×3 в радиусе семи ходов от цели против независимого BFS, все 512 лабиринтов 3×3 против релаксации рёбер, воспроизведение очереди BFS и обновлений A*, команды против комплексных поворотов и переправы 1–4 пар при вместимости 1–3 против поиска на множествах. Сохраняются пары без комплементарных литералов, каждый pivot, результат, тавтологичность, уникальность и поглощение. ## Планирование: кувшины, башня Ханоя и мир блоков

Ещё четыре типа повторно вычисляют решение из публичного условия: water_jug, tower_of_hanoi, blocks_world, hanoi_disk. Кувшины выполняют проверку достижимости через НОД и максимальный объём, затем BFS с родительскими ссылками; нулевая цель сохраняется и требует ноль действий. Записываются извлечения, каждый допустимый fill/empty/pour, посещённость, расстояния и восстановленный кратчайший план. Вместо копирования полного пути в каждом элементе очереди общий новый BFS хранит только родительские ссылки. Объёмы должны быть положительными целыми, цель — неотрицательным целым; некорректные параметры отклоняются.

Ханойская башня пересчитывает рекурсию из числа дисков и имён трёх разных стержней, записывает входы/возвраты вызовов и фактическое состояние стержней до/после каждого хода. Начальный стержень теперь правильно подставляется в условие вместо постоянного A. Поддерживается целое число дисков 0–12, пресеты по-прежнему 2–7; ограничение явно указано в инструкции. Визуальная hanoi_disk повторно вычисляет рекуррентное расстояние из pegs и отдельно подсчитывает диски на цели под ExecutionTrace. Размер картинки и расстояния между стержнями теперь зависят от ширины самого большого диска: восьмой диск не обрезается и не перекрывает соседний стержень.

Мир блоков выполняет BFS по опорам блоков, проверяет входные конфигурации (неизвестные опоры, несколько блоков на одной опоре, циклы), определяет свободные блоки и записывает реальные переходы. Повторный solve больше не дописывает шаги. Явный num_blocks вне 2–6 или нецелое значение теперь вызывает ошибку вместо молчаливого округления/ограничения; это остаётся ограниченным поиском, не обещанием масштабируемости на произвольное число блоков.

Проверяющие кувшинов и обычного Ханоя теперь симулируют действия из исходного состояния. Принимаются прежние локализованные текстовые планы и JSON-массивы действий (формат описан в условии), а не просто совпавшее число ходов. Ханой требует оптимальный план; кувшины принимают любой легальный достигающий цели план. Проверяются номера шагов, объявленные состояния/итоги и физическая допустимость каждого действия. Проверяющий мира блоков требует полного разбора каждого разделённого точкой с запятой хода; мусор и нераспознанные дополнительные действия не отбрасываются. Отсутствие ходов принимается только при явном ответе, когда цель уже достигнута.

В tests/test_planning_search_traces.py: полный перебор 1–3 кувшинов с объёмами 1–4 и всех целей до max+1 против независимого BFS с переливанием по единице; все пары корректных трёхблочных конфигураций против независимого графа; Ханой до восьми дисков с симуляцией и воспроизведением рекурсивного стека, малые размеры против BFS; все 3^n начальные раскладки визуального Ханоя до пяти дисков против BFS. Все четыре семейства проверены на всех уровнях, подмену сохранённых планов/ответов, а обычные планировщики — на обоих языках, идемпотентность, нулевые случаи, нестандартные стержни, альтернативные планы, некорректные параметры и попытки получить награду неполным/мусорным ответом. Аудит дополнен rendered_cached_plan: форматирование готового пути теперь выявляется и при наличии циклов.

Мир блоков заметно дороже из-за полного поиска кратчайшего плана и экспорта просмотренных переходов; ограничения пресетов сохранены явно. ## Публичные логические модели и вероятностные расчёты

Исправлены futoshiki, cryptarithmetic, knights_knaves, bayesian_reasoning, urn_probability. Совокупное покрытие независимыми регрессиями теперь составляет 250 типов.

Futoshiki больше не выбирает случайные клетки для шаблонных «шагов». Решатель конечных доменов использует таблицы строгих неравенств, ограничения различия строк/столбцов, распространение, MRV и откаты; вычисление зависит только от size и inequalities. Генератор строит неравенства по случайно переставленному латинскому квадрату и использует это свидетельство как начальный кэш, не повторяя дорогостоящий поиск Z3 при создании; solve всё равно решает условие заново. Поэтому обычные экземпляры разрешимы; пользовательские несовместимые ограничения по-прежнему приводят к доказанному «нет решения». Число неравенств выбирается из конечного набора, недопустимые параметры отклоняются вместо бесконечного цикла. Размер — целое 1–9, пресеты 3–7, координаты в условии явно от 0. Проверяющий принимает любую подходящую латинскую сетку, не сохранённый solution; дробные записи и посторонний текст не превращаются в клетки сетки. get_result сохраняет algorithm_trace и computation_inputs.

Числовой ребус решается по разрядам справа налево с учётом переносов, занятых цифр, ведущих ненулевых цифр и повторений букв. Записываются домены, назначения/откаты, каждое сложение по разряду, проверка выходной цифры и перенос. _mapping не является входом. Исправлен некорректный генераторский fallback: исчерпание попыток теперь generation_failed. Явный num_digits вне целых 2–6 вызывает ошибку вместо молчаливого ограничения. Проверяющий полностью разбирает назначения, отклоняя многозначные «цифры», дроби, повторы/лишние буквы и мусор. Несовместимое публичное равенство поддерживает ответ «нет решения» с повторной проверкой отсутствия подстановки.

KnightsKnaves ранее возвращал случайные роли независимо от произнесённых фраз; методы анализа противоречий были заглушками. Теперь каждое высказывание содержит явную polarity, совпадающую с ролью, названной в тексте. Проверяются восемь форм: о себе/другом, AND, включающее OR, одинаковые/разные роли, хотя бы один/ровно один среди всех перечисленных. Генератор создаёт фразы, согласованные с проверенным свидетельством, а solver перебирает все назначения из публичных высказываний и записывает истинность каждой фразы и её соответствие роли говорящего. Любая подходящая модель принимается; неоднозначность разрешена явно в условии. Роли генератора не участвуют в решении или проверке. Complexity 1–5 действительно задаёт 2–6 персонажей и 2/3/5/7/9 высказываний. Исправлены постоянное «три персонажа», английские названия ролей в русском тексте и изменение общего списка имён. Старые сохранённые экземпляры без polarity не восстанавливают потерянную связь текста с ролью автоматически; новый контракт применяется к новой генерации.

BayesianReasoning теперь выбирает параметры и формирует условие один раз при создании экземпляра. solve не меняет условие или состояние RNG и не дописывает шаги. Точные Fraction-расчёты раскрывают истинно-/ложноположительные массы, нормировку Байеса и полную вероятность двухзвенной цепи. В урнах исключены случайные номера контейнеров в объяснении; теперь считаются комбинации, благоприятные исходы для all/at_least/exactly, условные вероятности, равные веса контейнеров и сумма. Достаточное число предметов обеспечивается и при явном draws>8. Проверяются положительные целые count_containers/draws. Оба вероятностных проверяющих пересчитывают ответ из условия, допускают точную дробь или округление с погрешностью не более 0,00005 и отклоняют посторонний текст, NaN и значения вне [0,1]. Экспорт урн больше не теряет метаданные трассы.

Независимые проверки в tests/test_public_puzzle_inference.py: перебор латинских квадратов 2×2/3×3 и совместимых/противоречивых неравенств; перебор цифровых подстановок малых ребусов, SEND+MORE=MONEY и арифметика переносов; все булевы варианты восьми форм высказываний и сравнение логических моделей; урны против перечисления всех подмножеств предметов; байесовская цепь против перечисления совместных событий. Проверяются все уровни/подтипы, RU/EN, подмена скрытых результатов, идемпотентность, неизменность RNG/условия, неоднозначные и неразрешимые случаи, ошибки параметров и проверки ответов. Аудит дополнен random_solver_calls, чтобы случайные подстановки в solve не скрывались за наличием циклов. Поиск CSP и криптарифметика в общем случае экспоненциальны; уровень сложности не гарантирует одинаковое время на всех seed.

## Однозначность из открытого условия: сапёр и загадка Эйнштейна

Исправлены minesweeper_deduction, minesweeper_image и zebra_puzzle; суммарно отдельными регрессиями покрыты 253 типа. Оба семейства используют finite_csp и контрпример к ответу, а не скрытый эталон генератора.

В «Сапёре» все неоткрытые клетки выводятся как дополнение к revealed; вход — только размер, открытые числа и целевая клетка. Количество мин, mines, hidden, числа неоткрытых безопасных клеток и target_is_mine не входят в вычисление. Для каждой открытой клетки строятся точные допустимые бинарные наборы соседей с нужной суммой. Поиск отдельно проверяет гипотезы target=0 и target=1, записывает ограничения, распространение, ветви, конфликты и полные свидетели. Два совместимых статуса означают ambiguous_target, ни одного — inconsistent_clues; единственный статус доказывает ответ. Входные индексы переменных явно сопоставлены клеткам в первом событии.

Генератор сапёра использует тот же поиск вместо перебора всех 2^hidden расстановок. При исчерпании попыток он сообщает generation_failed, а не меняет число мин в запасном поле. Явные n/num_mines/extra_hidden теперь действуют вместо игнорирования kwargs: n — целое 2–8, число мин неотрицательное, есть хотя бы одна открытая клетка, число скрытых — 1–14. Нулевые значения сохраняются, неверные сочетания отклоняются. Проверяющий использует сертификат, привязанный к публичному условию; изменение условия требует новой проверки. Строгая классификация меток корректно обрабатывает not mine / not a mine и не вознаграждает слова mine в мусорном или противоречивом ответе.

У загадки Эйнштейна обнаружены три независимые ошибки: перестановка attr соседей без перестановки их категорий; отсутствие списка всех допустимых значений категорий в условии; отсутствие доказательства однозначности вопроса при случайных подсказках. Все три исправлены. Категории и все их значения теперь опубликованы, названия категорий и домов локализованы. Публичный query отдельно задаёт вопрос о позиции или владельце. Модель хранит позицию каждого значения и ограничивает перестановки категорий, равенство домов, соседство, строгое «слева», заданную позицию, первый/средний дом. Проверяются также данные меток first/middle, чтобы позиция не противоречила смыслу подсказки.

После первого решения запрещается найденный ответ (позиция значения либо его совпадение с найденным владельцем). Отсутствие второй модели доказывает единственность ответа, а не обязательно всей таблицы. Если генератор находит контрпример, он добавляет публичную позиционную подсказку, отличающую контрпример от исходного свидетельства, и повторяет проверку. Поэтому num_clues — начальный бюджет подсказок, фактическое количество может увеличиться, включая явный num_clues=0; уточнения видны в условии и экспорте. Ограничения генератора — 2–5 домов и категорий, начальный бюджет 0–100; неверные значения отклоняются вместо молчаливой подстановки/обрезания.

Проверяющий загадки принимает доказанный ответ отдельно или полную таблицу в штатном формате. Если таблица присутствует, проверяются номера строк, все значения/перестановки, каждая подсказка и соответствие ответа таблице; подмена solution/answer не влияет на проверку. Сертификат ответа привязан к размеру, публичным доменам, подсказкам и query. Решение по несовместимым/неоднозначным пользовательским условиям отклоняется вместо выдачи генераторского ответа. Solve не использует случайность и идемпотентен.

## Формальные утверждения и вывод родства

Исправлены contradiction и family_tree; текущее покрытие отдельными регрессиями — 259 типов.

У contradiction выявлено принципиальное ограничение старого контракта: программа не доказывала ложность утверждения из условий, а выбирала текст из помеченного списка бытовых/научных фраз. Списки не содержали явных предпосылок или вычислимого обоснования, поэтому такие метки не являются алгоритмическим доказательством истинности. Новая генерация contradiction намеренно меняет содержание задачи на поиск единственного ложного утверждения по опубликованным целочисленным определениям. Старый банк выведен из PROMPT_TEMPLATES и сохранён в docs/legacy_contradiction_facts.json со статусом unverified_legacy_data_not_used_for_generation; фактологическая корректность каждого старого элемента этим проходом не подтверждается. Старые примеры, опирающиеся на мировые знания, не получают задним числом формальный сертификат.

Определения вычисляются по порядку с точными целыми числами и операциями add/sub/mul; разрешены ссылки только на уже вычисленные переменные. Затем проверяется каждое сравнение eq/ne/lt/le/gt/ge, и заново собирается множество ложных утверждений. Ноль или более одного ложного утверждения дают ошибку expected_one_false_claim. false_statement_index и готовые строки statements не являются входом решения или проверки. Трасса записывает все операнды/результаты определений, оба значения и истинность каждого сравнения, итоговые индексы. Проверяющий пересчитывает данные, принимает номер от 1 либо точное ложное утверждение/штатный ответ, не извлекает случайное совпавшее число из мусора. get_result теперь сохраняет трассу и computation_inputs.

num_statements — целое 1–500 (пресеты 5–40), chain_depth — целое 0–20 (пресеты 2–6). Явные нулевые глубины сохраняются. Количество определений растёт как 2+num_statements*chain_depth; выполнение линейно по числу операций с учётом стоимости целочисленной арифметики. Это изменение схемы данных: новая задача использует definitions/claims, а не старую внешнюю базу фактов. Условия, подписи, описание каталога и примеры обновлены соответственно.

FamilyTree теперь строит родительские/брачные связи из опубликованных couples и child_groups, используя указанный пол. Старые parents/spouse и сохранённый role не читаются при решении или проверке. Для каждого найденного отношения строится явный путь с типами рёбер parent/child/spouse. Проверяются неизвестные участники, несколько несовместимых супругов, некорректные родители и циклы предков; отсутствие отношения и несколько разных отношений не превращаются в произвольный ответ. Проверяющий сравнивает полную нормализованную метку и использует сертификат, привязанный к публичным связям и вопросу. Неверная/отрицательная фраза не проходит по подстроке.

Сложность FamilyTree ранее не влияла на вопрос. Теперь уровни 1–2 выбирают путь из одного ребра, 3–6 — из двух, 7–8 — из трёх, 9–10 — из четырёх (двоюродные); relation_hops=1..4 задаёт длину явно. ## Проверка доказательств, следование, силлогизмы и аналогии

Исправлены natural_deduction, logical_entailment, syllogism и analogical; отдельными регрессиями теперь покрыты 259 типов.

NaturalDeduction повторно проверяет каждую строку из lines: синтаксис формулы, правило, число/тип/границы ссылок, формулы источников и соответствие результата MP, MT, AND_I, AND_E1/2. Ссылки с отрицательным индексом, вперёд, bool/float/string и ссылки в строке-посылке не принимаются. Список формул из JSON нормализуется к той же структуре, что и кортежи. Трасса показывает проверенные источники, заключение и исход каждой строки; первый неверный шаг завершает проверку. Генератор больше не заменяет сложный вывод минимальным MP после неудачи: вместо нарушения пресета выдаётся generation_failed. Уточнены правила извлечения левого/правого конъюнкта и язык условия. Проверяется именно правильность указанного вывода по правилам, а не только семантическая истинность его заключения.

LogicalEntailment перебирает означивания публичных переменных, вычисляет каждую подформулу с её операндами/результатом и показывает значения всех посылок/заключения. Первая модель с истинными посылками и ложным заключением — явный контрпример; при отсутствии такой модели записывается полный объём перебора. Неизвестный оператор больше не трактуется как iff. Несовместимые посылки по стандартной семантике влекут любое заключение; этот случай проверен отдельно. valid/_valid/_entails не являются входом ни одного нового решателя, а проверяющие заново вычисляют правильность и разбирают полные метки, не случайные yes/no-подстроки.

Syllogism пересчитывает все необходимые варианты занятости восьми регионов S/M/P. Для каждого кванторного утверждения сохраняются относящиеся к нему занятые регионы, истинность и затем общая проверка контрмодели. В условии явно указано: термины могут быть пустыми; all/no не требуют существования, some/some_not требуют. Исправлены двойные скобки {{x}}/{{y}}, из-за которых вместо терминов выводились шаблонные имена, и выбор языка до инициализации BaseTask. Явные figure=1..4 и mood=(quantifier,quantifier,quantifier) работают; пресеты выбирают одну из четырёх фигур. Это разнообразие структуры, а не обещание строгого возрастания трудности: семантическая модель по-прежнему ограничена тремя терминами и 256 вариантами занятости. Проверяющий корректно различает valid/invalid/not valid и отклоняет мусор/конфликтующие метки.

Старый AnalogicalTask не вычислял аналогию: любой свободный текст получал одинаковый шаблонный ответ. Новый контракт — числовые пары examples и query в явно опубликованном конечном классе y=a*x^k+b. a — ненулевое целое с модулем не больше coefficient_bound (1–8), b в диапазоне ±offset_bound (0–20), k=1..max_power (1–3). Генератор выбирает правило только как свидетельство построения, но решение перебирает все допустимые правила, считает предсказания каждого примера и собирает множество ответов для query. Несовместимые примеры дают inconsistent_examples, разные предсказания — ambiguous_prediction; несколько правил с одним предсказанием допустимы. При генерации неоднозначность устраняется дополнительным опубликованным примером, query не включается в обучающие примеры. Сложность меняет реальные границы коэффициентов/степеней; generate_random_analogical_task передаёт параметры и difficulty. Произвольный description без структурированных examples явно отклоняется вместо фиктивного ответа. Контракт этой задачи изменён; поддержка произвольных текстовых/словесных аналогий этим проходом не добавляется.

Независимые проверки в tests/test_proof_and_analogy_traces.py: все правила вывода и неверные ссылки; звуковость принятых малых шагов против таблиц истинности; все 256 комбинаций четырёх фигур и 64 кванторных настроений силлогизма против независимых операций над множествами; контрмодели; следование против SymPy, включая несовместимые посылки; воспроизведение каждого кандидата числовой аналогии и случай x/x^3, совпадающих на -1,0,1, но различающихся на 2. ### Дополнительный проход: очереди и стабильные CSP-инстансы

`os_scheduling` пересчитывает SJF, FCFS и SSTF из опубликованных bursts/jobs/start/reqs. Сохранённые order/answer не используются как вход. Для SJF/FCFS записаны ключи сортировки с разрешением ничьих по номеру, затем приход, длительность, часы, простой, начало/конец, ожидание и накопленная сумма каждой заявки. SSTF записывает все оставшиеся запросы с их номерами и расстояниями перед каждым выбором; одинаковые цилиндры сохраняются, включая нулевое перемещение. Старый set(reqs) терял повторные запросы. Проверяющий заново считает ответ и требует целое число целиком после извлечения answer-блока.

Явные n=1..500 и span=1..1_000_000 теперь используются и валидируются. Для SSTF n не превышает span: генератор выбирает n различных цилиндров, исключая начальный, без выделения списка на весь диапазон. Решатель, в отличие от генератора, принимает повторные запросы. Случай n=1 не обращается ко второй заявке. Неизвестный подтип больше не превращается неявно в SSTF. SJF/FCFS требуют O(n log n) сортировки, SSTF — O(n²); сохранение всех расстояний SSTF также занимает O(n²), хотя число событий линейно. Это ограничение существенно при массовом экспорте трейсов.

`csp_reasoning` генерирует инстанс при создании, а solve больше не меняет условие и не потребляет RNG. Вместо двух фраз о результате SMT выполняется явный finite-domain поиск: начальные домены/таблицы ограничений, удаление неподдерживаемых значений, конфликты, выбор ветви, возвраты и найденная модель. Латинский квадрат использует опубликованные клетки, row/column all-different, размер 2..9 и clues=0..size², включая ноль. Скрытая построенная таблица не является входом решения. Мини-Kakuro использует только четыре опубликованные суммы и ровно два неравенства строк, указанные в условии: одинаковые значения в столбце допустимы. Ни одно из этих семейств не обещает единственность решения; проверяющий принимает любое корректное заполнение, отвергая минусы, дроби, повторные назначения переменной и посторонний текст. Невыполнимый опубликованный инстанс вызывает ошибку, а не перегенерацию.

Мини-Kakuro остаётся фиксированным блоком 2×2, это не масштабируемая сетка Kakuro: size кроме 2 и clues кроме 0 для этого подтипа явно отклоняются. Пресеты старших уровней выбирают этот подтип, не увеличивая его форму. У латинского квадрата явный size меняет размер, а clues — точное число подсказок; поиск в общем случае экспоненциальный. Генератор строит перестановки строк циклического квадрата и не обещает равномерную выборку всех латинских квадратов.

Независимые тесты: симуляция CPU по единицам времени для 81 очереди SJF и 729 очередей FCFS; независимый поиск SSTF по фронту расстояний для 1024 очередей с повторами; все 81 частичные таблицы 2×2 против перебора латинских квадратов; все выполнимые векторы четырёх сумм мини-Kakuro против полного перебора 9⁴ назначений. ### Дополнительный проход: мини-SAT и универсальные целочисленные утверждения

`sat_smt_mini` теперь создаёт КНФ один раз в конструкторе. Повторное solve не меняет формулу, условие или RNG и не накапливает старые шаги. Режим sat строит каждую дизъюнкцию совместимой с выбранным свидетелем: раньше случайная КНФ могла оказаться UNSAT даже при target="sat". В режиме unsat строится вынужденная цепочка импликаций с противоположным конечным литералом, а остальные дизъюнкции согласованы с цепочкой до последнего отрицания. Число дизъюнктов ровно num_clauses, а не num_clauses+2. Длина противоречивой цепочки растёт до min(num_vars,num_clauses−1); это управляемые экземпляры с известным при построении сертификатом, не равномерная выборка случайных КНФ и не гарантия трудности каждого примера.

Решение независимо выполняет DPLL по опубликованной КНФ. События содержат значение каждого литерала, текущее присваивание, истинность дизъюнкции, вынужденное единичное присваивание с номером дизъюнкта, ветви, конфликты, возвраты и итоговую полную модель. Поддерживаются пустая КНФ (истина), пустая дизъюнкция (ложь), повторы литералов, тавтологии и неиспользованные переменные. Номера переменных в JSON-литералах исходного computation_inputs начинаются с нуля; в событиях и условии — x1, x2, ... . Границы генератора: num_vars=1..64, num_clauses=0..256; режим unsat требует хотя бы двух дизъюнктов. target=mixed с 0/1 дизъюнктом строит выполнимый экземпляр. Имя SAT/SMT сохранено для совместимости, но это именно булева КНФ, не новый решатель арифметических SMT-теорий.

Проверяющий SAT принимает любое полное удовлетворяющее присваивание, а не только модель, выбранную DPLL; проверяются все исходные дизъюнкции. Пропущенные/повторные/лишние переменные, неверные булевы значения и посторонний текст отклоняются. UNSAT принимается только после повторного DPLL. Свободные переменные модели дополняются False. В общем случае DPLL экспоненциален; полный трейс хранит все посещённые проверки, включая неудачные ветви. Не обещается линейное время произвольной КНФ.

`proof_cases_counterexample` больше не выбирает ответ по скрытому truth-флагу. Генератор один раз формирует структурированное утверждение, опубликованное в условии и computation_inputs. Сохранены четыре прежних направления: чётность, делимость, условное утверждение для нечётных n, разность квадратов. Русские условия больше не подставляют английские утверждения. Для делимости с целыми коэффициентами проверяются все классы по L=НОК(модуль вывода, модуль посылки), с явным объяснением полноты: n≡r mod L сохраняет истинность посылки и остаток целочисленного многочлена. Это доказательство для всех целых, а не проверка первых нескольких чисел. События показывают применимость посылки, каждый шаг схемы Горнера, значение и остаток; первый ненулевой остаток даёт реальный контрпример.

Для тождеств решатель раскрывает (n+s)(n+s) по произведениям коэффициентов, вычитает n² и правую часть. Нулевая разность коэффициентов доказывает тождество; для ненулевого многочлена степени d ищется контрпример среди d+1 различных целых — этого достаточно по ограничению на число корней. Проверяющий принимает любой указанный целый контрпример, включая отрицательный, только если посылка истинна, а вывод ложен; TRUE требует полного пересчёта доказательства. Подмена final_answer/truth/answer не влияет на решение.

Дополнительные параметры: coefficients — от 1 до 9 целых коэффициентов по возрастанию степени, каждый в ±1000; modulus=2..256 для модульных направлений; shift=1..1000 для разности квадратов. Явные coefficients/modulus задают само утверждение, поэтому truth_bias не гарантирует его истинность после такого переопределения. Параметры модульного многочлена несовместимы с factorization_form и явно отклоняются. Пресеты по-прежнему выбирают несколько фиксированных форм утверждений; разнообразие полиномов/модулей задаётся явными параметрами. Это не доказательство произвольных текстовых теорем.

Независимые проверки tests/test_sat_and_integer_proofs.py: все малые КНФ с двумя переменными и до трёх дизъюнктов против таблиц истинности; 100 случайных КНФ против Z3; воспроизведение оценок литералов, оснований единичных выводов и конфликтов; противоречие, требующее провала обеих ветвей; точное число дизъюнктов и гарантии target на 30 seed каждого режима; 64-шаговая вынужденная цепочка. Для целочисленных утверждений — полиномы/остатки и раскрытие тождеств против SymPy, полнота перечисления классов, промежуточные шаги Горнера и случай n(n−1), совпадающий с делимостью на 3 при n=0,1, но опровергаемый n=2. ### Дополнительный проход: комбинаторная оптимизация

`combinatorial_optimization` (рюкзак 0/1, покрытие множеств, симметричный TSP) теперь строит экземпляр один раз. Повторное solve пересчитывает опубликованные items/capacity, universe/sets или matrix; не генерирует новое условие, не использует RNG и не накапливает старые шаги. Раньше все три подтипа генерировались внутри solve, а решение содержало только фразу «сравниваем кандидатов».

Точный рюкзак записывает каждую ячейку DP: не брать предмет, взять при достаточной вместимости и максимум, затем полное восстановление выбранных индексов. Приближённый режим сортирует по точным Fraction-отношениям ценности к весу (не по float), ничьи — по меньшему индексу; на каждом предмете сохраняет проверку вместимости, решение взять/пропустить, общий вес/ценность. Отрицательные ценности и неположительные веса решателем отклоняются; вместимость может быть нулевой. Генератор использует положительные веса/ценности.

Точное покрытие использует BFS по маскам уже покрытых элементов. Записаны соответствие битов элементам, маски множеств, извлечения очереди, каждый проверенный переход OR с прежним расстоянием и признаком обновления, восстановление покрытия. Первое достижение полной маски в BFS даёт минимум числа множеств. Жадный режим сохраняет все новые элементы каждого кандидата, выбранное множество и оставшиеся непокрытые элементы; ничьи разрешаются по индексу. Генератор гарантирует, что объединение всех множеств равно универсуму, и поддерживает n=1. Раньше случайный экземпляр мог вообще не иметь покрытия, а решатель возвращал размер 0/частичное покрытие. Теперь непокрываемый опубликованный экземпляр вызывает явную ошибку.

Точный TSP — Held–Karp с базовыми состояниями, всеми кандидатами каждого состояния (маска, конечная вершина), стоимостью перехода, выбранным предшественником, всеми вариантами замыкания в 0 и восстановлением цикла. Приближённый режим — ближайший сосед (ничья по меньшей вершине) плюс один полный лексикографический проход 2-opt с немедленным принятием строгих улучшений. Записаны расстояния до всех непосещённых кандидатов и каждый обмен: четыре конца рёбер, удалённая/добавленная стоимость, delta, принятие и актуальный маршрут. Исправлены границы циклов: обмены с замыкающим ребром больше не пропускаются. Это один проход, не обещание локального оптимума 2-opt. Матрица должна быть квадратной, симметричной, с целыми неотрицательными расстояниями и нулевой диагональю; не предполагается неравенство треугольника. n=1 имеет длину 0 и маршрут [0,0], n=2 также поддерживается.

Ресурсные пределы теперь явные: n=1..100 для рюкзака и приближённых режимов; n=1..12 для точного покрытия/TSP. Старое молчаливое уменьшение TSP до 9/12 вершин убрано. Запрошенный размер либо сохраняется, либо явно отклоняется. Вход решателя рюкзака дополнительно ограничен 100 предметами и вместимостью 0..5000. Точный рюкзак имеет O(n*C) вычислений/трейса, точное покрытие — до O(m*2^|U|), Held–Karp — O(n²*2^n) вычислений; сохранение всех кандидатов/неудачных переходов также расходует память. Приближённый TSP делает O(n²) обменов, но экспорт снимка всего маршрута после каждого обмена даёт O(n³) объём полного трейса. Большие параметры следует выбирать с учётом размера данных, а не только числа шагов.

Контракт approx теперь явно раскрыт в RU/EN условии: принимается любое допустимое решение не хуже описанной детерминированной эвристики; улучшать её результат разрешено. Контракт exact требует оптимального допустимого решения. task.verify проверяет весь сертификат: индексы и отсутствие повторов, вместимость/полное покрытие/посещение всех вершин, правильность объявленной целевой величины, затем сравнивает с пересчитанным оптимумом или эвристическим порогом. Другие оптимальные подмножества/циклы и более удачные приближённые решения принимаются. Отрицательные/лишние индексы, bool вместо индекса, неполные маршруты, выдуманные значения и посторонний текст отклоняются. Этот контракт относится к instance.verify; сравнение только с референсной строкой без входного экземпляра не проверяет альтернативные сертификаты. Приближённый режим не выдаётся за оптимум и не обещает универсального отношения аппроксимации.

### Дополнительный проход: Mastermind, поиск арифметической ошибки, неотрицательность

`mastermind` больше не возвращает self.secret. Решатель получает только длину, алфавит и опубликованные догадки с exact/partial, затем выполняет поиск по префиксам. Для каждой подсказки записывает нижнюю/верхнюю границу числа точных совпадений и общих совпадений с учётом кратностей. Нижняя граница общих совпадений — сумма min(count_prefix[d],count_guess[d]); верхняя добавляет min(оставшиеся позиции, ещё не использованные количества значений догадки). Если требуемое число вне диапазона, ни одно продолжение префикса не подходит: записывается отсечение. Для полного кода диапазоны схлопываются и проверяют точную обратную связь. Поиск полного пространства с одним найденным кодом доказывает единственность; ноль решений даёт inconsistent_clues, два найденных — ambiguous_clues с признаком неполного дальнейшего перебора. Тайная строка не является входом решения/трейса и может быть подменена без изменения результата.

Генерация Mastermind теперь фильтрует оставшихся кандидатов только новой подсказкой, вместо повторной проверки всех старых подсказок на всём пространстве кодов. Дубликаты и неинформативные случайные догадки не добавляются; догадка, равная секрету, не публикуется. Если случайный этап не обеспечил единственность, следующий кандидат, отличный от секрета, становится догадкой и гарантированно исключает хотя бы самого себя. Есть предел 128 опубликованных подсказок; при невозможности закончить в нём генератор явно отказывает, а не раскрывает секрет или уменьшает параметры. Гарантия успешной генерации при всех возможных последовательностях RNG в этом пределе не заявляется. L=1..8, C=1..10 действительно передаются из kwargs, с явным ограничением C^L≤32768. Прежние параметры L/C игнорировались. Случаи единственного символа и значения 10 проверены. Условие уточняет повторы и правило однократного учёта каждого совпадения.

Mastermind task.verify проверяет весь код по всем опубликованным подсказкам, не по секрету. При генерации/solve единственность проверяется отдельно; сам предикат verify принимает любой код, совместимый с подсказками, и не запускает повторный поиск единственности. Это существенно для вручную изменённых неоднозначных экземпляров: solve их отвергает, а verify является проверкой удовлетворения ограничений. Посторонний текст, лишние числа, знаки минус, дроби и значения вне алфавита отклоняются. Объём пространства остаётся экспоненциальным C^L; префиксные границы сокращают перебор, но не делают произвольный Mastermind полиномиальным. Полный трейс может быть большим.

`find_the_error` заново вычисляет каждое опубликованное равенство +/−/*, записывает операнды, операцию, заявленное и вычисленное значения, разность и истинность. Сохранённые fifth-field correct_value и _error_index исключены из computation_inputs и решения. Проверяются все строки, не только заранее испорченная. Ровно одно неверное равенство — явный инвариант; ноль/несколько вызывают expected_one_incorrect_step. Неизвестная операция больше не трактуется как умножение. num_steps=1..1000 задаёт точное число строк (раньше минимум молча повышался до 2); max_number=1..1_000_000, ops — непустой список/кортеж из +/−/*. Проверяющий пересчитывает задачу и принимает только номер строки целиком после извлечения answer-блока.

`inequality_proof` решается по опубликованным a,b,c, не по _always_nonneg. При a>0 записаны b², 4ac, дискриминант, точная рациональная вершина и минимум −D/(4a). Отрицательный минимум даёт конкретный контрпример. При a=b=0 рассматривается знак константы. При a=0,b≠0 берётся x=−(|c|+1)/b: значение c−|c|−1 строго отрицательно. При a<0 выбирается |x|=|c|+1 со знаком, делающим bx≤0, и явно вычисляется отрицательное значение. Каждый ответ NO содержит рациональный свидетель с разложением ax², bx, c и суммой; вычисления Fraction не зависят от ошибок float. Проверяющий использует полные YES/NO-метки и синонимы, не случайные подстроки и не старый final_answer.

В генераторе неотрицательных трёхчленов исправлен max_coeff: раньше при max_coeff=M слагаемые q²+r и 2pq могли сильно превышать M. Теперь a выбирается в 1..M, |b|≤min(M,isqrt(4aM)), c между ceil(b²/(4a)) и M; все три коэффициента ограничены M и D≤0. Случайная ветвь берёт коэффициенты в ±M, включая вырожденные линейные/постоянные случаи. Параметр M=1..1_000_000 валидируется без молчаливого преобразования float/bool в int. Дополнительные явные a,b,c принимаются только все вместе как целые; для них M ограничивает генерацию, а не значения явно заданного экземпляра. Пресеты не гарантируют строгое возрастание трудности каждого сэмпла.

### Физический проход: импульс, столкновения и теплопередача

Проверены `momentum` и `heat_transfer`, всего восемь подтипов. Это идеализированные учебные модели, а не симуляция реальных материалов с температурно-зависимыми свойствами. Коэффициенты c/λ заданы в условии; точность рациональной арифметики не означает точность этих приближённых материальных констант для любого эксперимента.

В momentum решение теперь выполняется по активным данным условия, с точными Fraction из десятичной записи входов. Для проекции импульса/силы сохраняется знак; допускаются нулевая скорость, нулевая сила и нулевая длительность, отрицательная длительность и неположительная масса отклоняются. Явно заданная скорость второго тела v2 теперь поддерживается в обоих видах столкновений и передаётся через фабрику. Все скорости — знаковые проекции на одну ось; внешним импульсом пренебрегаем, модель ньютоновская и одномерная. Входы со |v|>10000 м/с отклоняются как выходящие за выбранную нерелятивистскую область. Равные скорости — вырожденный нулевой удар: скорости не меняются, диссипация нулевая.

Упругое столкновение вычисляется через приведённую массу и импульс взаимодействия. В трейсе есть все действия и реальные проверки: p_initial=p_final, K_initial=K_final, относительная скорость меняет знак. Последняя проверка отличает физический результат удара от тривиального неизменённого решения системы сохранения энергии/импульса. Полностью неупругое столкновение вычисляет общую скорость, импульс до/после, кинетические энергии и диссипацию; потеря энергии сверяется с μ(v1−v2)²/2 и проверяется на неотрицательность. Кинетическая энергия при слипании не объявляется сохраняющейся.

В теплопередаче устранена физически неверная генерация нагрева льда выше 0 °C по одному Q=mcΔT. Для модели без фазового перехода область льда −100..0 °C, жидкой воды 0..100 °C, перечисленных металлов −100..200 °C. Это консервативные границы выбранной учебной модели, не универсальные границы существования веществ. Коэффициент c считается постоянным, даже если в реальности он зависит от температуры. Поддерживается охлаждение: знак Q соответствует теплоте, полученной телом. Плавление льда — отдельный процесс: лёд и конечная вода имеют 0 °C, без предварительного нагрева/последующего подогрева и потерь, Q=λm. Пересечение фазовой границы в heat_capacity явно отклоняется вместо неверного численного ответа.

Смешивание — только две порции жидкой воды с одинаковым постоянным c, без потерь и теплоёмкости сосуда. Вычисляется равновесная температура; фактически проверяются равенство полученной и отданной теплоты и нахождение результата между исходными температурами. Температуры в °C — координаты на одной шкале, разности имеют тот же численный размер, что в K; это специализированная модель, не общий движок арифметики аффинных температурных единиц.

КПД — циклическая тепловая машина с ΔU_cycle=0: W=Q1−Q2, проверка Q1=W+Q2, η=100W/Q1. Требуются 0<Q2≤Q1; Q1=Q2 даёт вырожденный нулевой КПД. Обратимость и температуры резервуаров не заданы, поэтому проверка предела Карно здесь не заявляется. Исправлена генерация Q2 при явно малом Q1: старое randint(5000,int(0.7*Q1)) могло падать даже до вычисления задачи. Теперь Q2 строится как точная доля Q1, а не через бинарные артефакты float. Отрицательные/нулевые входные теплоты и Q2>Q1 явно отклоняются. Неиспользуемые параметры других подтипов больше не генерируются.

Каждое действие несёт вычисляемую размерность (M,L,T,Θ): при умножении/делении показатели складываются/вычитаются, при +/− должны совпадать. Единицы результата сверяются с полученной размерностью, балансы вычисляют действительный остаток. JSON-трейс хранит исходные величины, операнды/результат/размерности каждого действия, проверки и выходы. computation_inputs содержит только параметры модели и данные условия; готовые ответы туда не подмешиваются. Сохранённый physical_outputs/final_answer не используется при verify: модель пересчитывается заново. Повторное solve не использует RNG и не меняет условие.

Проверяющий разбирает весь ответ и учитывает единицы: Дж/кДж/МДж, м/с и км/ч, Н·с и кг·м/с, °C и K с точным сдвигом 273,15. Если единицы не указаны, число трактуется в требуемой условием единице. Число КПД трактуется в процентах, не как доля единицы. Поддерживаются десятичная запятая, точка, научная запись, обычная дробь и математический знак минуса. Для упругого столкновения обязательны обе именованные скорости v1_out/v2_out, порядок допускается любой; повторные/отсутствующие имена, неверные единицы, неверный знак и посторонний текст отклоняются. В условии объявлено округление до четырёх десятичных знаков, реализация использует точное ties-to-even, абсолютный допуск 0,000051 в требуемой единице. Это не прежний широкий относительный допуск в проценты. При пересчёте ответа из альтернативных единиц допуск относится к требуемой единице. Вводы конечны и ограничены модулем 10^12; массовые/тепловые/временные числа не могут быть bool. Парсер ограничивает размер и показатели научной записи, не исполняет выражения.

Фабрики physics/generators теперь передают параметры экземпляра, output_format и reasoning_mode для обоих семейств. Ранее часть этих настроек терялась, а фабрики возвращали ещё не решённый объект. Классы сохранены по старым путям импорта и с прежними именами подтипов; v2 по умолчанию ноль. Формат ответа упругого столкновения явно указан в условии и теперь однозначно именует обе выходные скорости.

### Колебания, волны и проверка сохранённых физических датасетов

Проверены `oscillations` и `waves`: десять подтипов. Исправлены нарушения контракта: harmonic просил период и максимальную скорость, но финальный ответ содержал период и частоту; spring просил период и обычную частоту, но выдавал угловую. ### Энергия, работа и динамика с явными допущениями

Проверены `energy` и `dynamics`, всего 12 подтипов. Старые базовые формулы в основном были учебно верными, но условия не фиксировали необходимые допущения, параметры могли быть физически недопустимы, фабрики теряли явные аргументы и режимы, а промежуточные значения преждевременно округлялись. Новые реализации используют точные рациональные/символьные операции и пять согласованных осей размерности; каждый solve пересчитывает только данные условия, не потребляет RNG и не доверяет сохранённому ответу.

Для работы заданы постоянная сила и предписанное перемещение; F/s — неотрицательные модули, угол между векторами 0..180°. Работа относится к указанной силе, а не автоматически ко всей системе. При угле 90° cos(π/2) равен точно нулю, без численного остатка math.cos; при углах >90° работа отрицательна. Углы переводятся из градусов в радианы явно через π/180, затем вычисляется скалярное произведение. Нулевые сила/перемещение поддержаны. В кинетической энергии v — знаковая проекция одномерной скорости; энергия неотрицательна при обоих направлениях. В потенциальной энергии h — координата относительно объявленного U(0)=0: отрицательная h даёт допустимую отрицательную U. Это отличается от высоты падения, которая должна быть неотрицательна.

Мощность определена как средняя P=W/Δt, со знаковой работой и строго положительным интервалом. Нулевая длительность отклоняется, средняя мощность не выдаётся за мгновенную. В сохранении энергии начальная скорость v0 явно задаётся (вверх положительно), по умолчанию ноль; старое условие «тело падает» не оговаривало покой. Расчёт использует v_impact²=v0²+2gh, затем отдельно вычисляет начальные K/U и конечную K и проверяет их равенство. Ответ — модуль скорости у плоскости y=0, не знак вертикальной проекции. Масса сокращается из скорости, но участвует в энергетической проверке. Модель ньютоновская, без сопротивления, g постоянно; входные/полученная скорости ограничены 10000 м/с как выбранной областью модели. Случай h=v0=0 рассматривается как нулевой граничный результат.

В динамике F и a — знаковые проекции суммарной силы/ускорения в инерциальной системе. Для weight явно задана неподвижная горизонтальная опора без других вертикальных сил: вес — сила давления тела на опору, равная по модулю нормальной реакции, а не универсальное утверждение «вес всегда mg». Friction определён как модуль кинетического трения скользящего тела на горизонтальной плоскости, N=mg, направление против скорости; статическое трение не подменяется μN. μ=0 разрешено, μ<0 отклоняется, произвольного физически неверного ограничения μ≤1 нет.

Наклонная плоскость явно гладкая, 0≤θ≤90°, других сил кроме тяжести/реакции нет, положительное направление вдоль плоскости вниз. Вычисляются обе проекции тяжести, нормальная реакция, их квадратичная норма и тангенциальное ускорение; проверяется F_parallel=m*a_parallel. При θ=0 результирующая вдоль плоскости нулевая, при 90° равна mg. Нормальная реакция не выдаётся за дополнительную тангенциальную силу.

Для tension условие теперь однозначно задаёт идеальную машину Атвуда: обе массы свободно подвешены, одна натянутая невесомая нерастяжимая нить, неподвижный невесомый блок без трения, грузы ещё не достигли ограничителей. Алгоритм получает знаковое ускорение a=(m2−m1)g/(m1+m2), затем независимо строит T=m1(g+a) и T=m2(g−a). В трейсе проверены одинаковое натяжение, оба уравнения Ньютона, T>0 и |a|<g. При равных массах a=0, T=mg. Другие схемы блока или нить с массой/упругостью не обещаются этим подтипом.

Требуются конечные численные параметры, положительные массы/g и корректные области углов/времени. Активные параметры передаются фабриками вместе с reasoning_mode/output_format; неизвестные подтипы вызывают ошибку вместо пустого условия. Пользовательские g/v0 действительно участвуют в задаче. Запрошенный output сохранён с 12 значащими цифрами, не менее 10 объявлено в условии; допуск относительный 10^-9. Точный ноль оценивается как точный ноль. Проверяющий пересчитывает модель, проверяет весь числовой ответ и единицы, включая Н/кН/мН, Вт/кВт/МВт, Дж/с и м/с². Перепутанные энергия/сила/мощность и неверный знак отклоняются. Полные JSON-трейсы содержат исходные величины, все операции/размерности и фактические остатки тождеств; готовые ответы не помещаются во входы.

## Кинематика и достижимость баллистических состояний

Проверены kinematics (8 подтипов) и projectile_motion (4 подтипа). Общая trajectory_models исполняет точные символьные операции с размерностями и сохраняет их в algorithm_trace; computation_inputs содержит только опубликованные исходные величины. Кэшированные vx/vy/дальность/высота/время не используются при решении или проверке ответа. Совместимые производные атрибуты projectile_motion теперь хранятся как SymPy-числа с 40 цифрами, а не float: это не дополнительные исходные данные.

Равномерное движение различает путь |vt| и знаковое перемещение; find_velocity использует именно знаковое перемещение. При постоянном ускорении путь вычисляется по участкам монотонности x(t): находится t_turn=-v0/a, проверяется строгое попадание внутрь интервала, затем суммируются |x(t_next)-x(t_previous)|. Разворот на границе не удваивает участок; t=0, v0=0, a=0 и отрицательные проекции обрабатываются явно. Круговое движение проверяет vT=2πr и a_c*r=v². Это идеальные модели с постоянными параметрами в инерциальной системе.

В бросках v0 имеет приоритет над совместимым v, включая явный ноль; дальность больше не игнорирует v0. Начальные скорость, угол и g публикуются с теми же числовыми значениями, которые поступают в расчёт. Скрытое округление условия при расчёте из других чисел устранено. По умолчанию скорости вертикального броска выбираются с шагом 0,001 м/с в диапазоне сложности: прежние шесть скоростей низшего уровня исчерпывались при исключении повторов. Явно переданные параметры не округляются.

Полёт определён без сопротивления, при постоянном положительном g, старте и посадке на одной горизонтальной плоскости, угле 0–90°. Трейс содержит компоненты скорости, время апогея/полёта, высоту/дальность и проверку нулевой высоты при возвращении. Для скорости на высоте проверяется достижимость относительно апогея именно данной траектории, затем восстанавливаются восходящее и нисходящее времена и вертикальные скорости, обе координаты y(t) и энергетическое тождество. В апогее совпадающие состояния отмечены как одно время. Вещественность sqrt(v0²−2gh) сама по себе не гарантирует достижимость высоты наклонной траекторией.

Параметры конечны; ограничения размеров чисел и допустимой скорости модели проверяются. g/r/T положительны, интервалы времени неотрицательны (для деления на время — строго положительны). Отрицательная начальная скорость броска, высота ниже стартовой плоскости или выше апогея отклоняются. Ответы имеют 12 значащих цифр, относительный допуск 10^-9, точный ноль требует нуля; поддерживаются совместимые единицы. Это не модель сопротивления, вращения Земли, релятивистского движения или произвольной высоты посадки.
